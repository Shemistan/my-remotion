# Протокол исследования репозитория

Инструкция для агента-исследователя: как превратить один репозиторий (или
его срез) в записи базы. Выполняется для каждого репозитория из
`repositories.json`; результат должен проходить `python3 tools/kb.py check`.

## Вход

- `REPO_ID` — ключ из `repositories.json` (= имя каталога в `components/`).
- `SRC` — абсолютный путь к исходникам репозитория.
- `SLICE` — необязательный срез (подкаталог/группа компонентов) для больших
  библиотек; тогда файл части называется `capabilities-<slice>.jsonl`.

## Сначала прочитать

1. `knowledge/README.md` — схема записи и правила.
2. `knowledge/taxonomy.md` — допустимые значения всех перечислений.
3. `knowledge/components/_TEMPLATE.md` — шаблон карточки.
4. Эталонные карточки: `components/remotion-bits/animated-counter.md`,
   `staggered-motion.md`, `bit-bar-chart.md` и их строки в
   `components/remotion-bits/capabilities.jsonl`.
5. `knowledge/compatibility/rules.md` — как классифицировать.

## Шаги

1. **Инвентаризация.** `ls`/`find` по `SRC` без `node_modules`, `dist`,
   `build`, `.git`, `coverage`. Найти: компоненты, примеры/демо/stories,
   документацию, лицензию (`LICENSE*`, `package.json → license`).
2. **Отбор.** Записывать компоненты, которые дают картинку, осмысленную в
   видео: текстовые эффекты, фоны, частицы, графики, диаграммы, карточки,
   списки, счётчики, переходы, 3D, mockup-и устройств, терминалы.
   **Пропускать** чисто интерактивные контролы (кнопки, инпуты, тогглы,
   аккордеоны, табы, скелетоны, прелоадеры, курсоры, меню, диалоги) — их
   перечислить одной строкой в `compatibility/<REPO_ID>.md` с причиной.
   Крупные чартовые библиотеки описывать по **типам графиков/диаграмм**
   (`kind: chart-type` / `diagram-type`), а не по внутренним модулям.
3. **Чтение исходников каждого отобранного компонента.** Нужно увидеть:
   props/типы (имена, типы, значения по умолчанию), механизм анимации
   (`useCurrentFrame`? `motion`? CSS `@keyframes`? rAF? `setInterval`?
   Canvas/WebGL? GSAP? three?), DOM-зависимости (`useRef`+измерения,
   `IntersectionObserver`, `window`), события (hover/scroll/drag),
   асинхронность (`fetch`, динамический import). README — только как
   подсказка, факты — из кода.
4. **Классификация** по `compatibility/rules.md`; флаги — все, что
   найдено в коде, даже если класс `native`.
5. **Запись.** Для каждого компонента:
   - карточка `components/<REPO_ID>/<slug>.md` по шаблону, ≤80 строк,
     заголовок содержит `` `<REPO_ID>/<slug>` ``;
   - строка в `components/<REPO_ID>/capabilities.jsonl` (или
     `capabilities-<SLICE>.jsonl`), все поля схемы, `card` =
     `components/<REPO_ID>/<slug>.md`.
   `slug` — kebab-case имени компонента (`BlurText` → `blur-text`,
   `BarChart` → `bar-chart`); для примеров-сцен с префиксом из реестра
   репозитория, если он есть (`bit-bar-chart`).
6. **Сводка репозитория** `compatibility/<REPO_ID>.md`: лицензия и
   ограничения; общий стек анимации; типовые адаптации для этой библиотеки;
   что пропущено и почему; чего не удалось выяснить.
7. **Проверка.** Из корня worktree:
   `python3 tools/kb.py check --repo <REPO_ID>` — до зелёного. Все пути
   должны существовать (проверка идёт относительно корня, где лежат
   `templates/` и `official_skills/`).
8. **Отчёт** в финальном сообщении: число записей по классам
   совместимости; JSON-объект для `repositories.json` (поля `license`,
   `license_notes`, `purpose`, `stack`, `components_dirs`, `has_examples`,
   `notes`); что пропущено; что неясно.

## Жёсткие правила

- Не изменять исходный репозиторий, не запускать в нём `git` (guard
  блокирует), не ставить зависимости, не рендерить, не коммитить.
- Не выдумывать props, пути, значения по умолчанию. Нет данных — пустое
  «нет данных» в тексте и `unknown` в классе с объяснением.
- Пути в `source_files`/`docs` — от корня проекта (`templates/...`,
  `official_skills/...`), проверены `ls`.
- Тексты по-русски; имена props, файлов, пакетов — как в коде.
- `voiceover_cues` — не меньше трёх живых фраз, какие могли бы прозвучать
  в озвучке ролика и под которые подходит именно это решение.
- Один компонент — одна запись; не объединять разные компоненты. Пресеты
  одного компонента с одинаковым визуалом — одна запись с перечислением
  вариантов в `inputs`.
- `verification` ≤ `static-review` (рендер не делался).
- Карточка не копирует код: максимум сигнатура props и 3–5 строк
  характерного фрагмента.
