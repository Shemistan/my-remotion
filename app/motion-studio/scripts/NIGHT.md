# Цикл качества по запросу (`./quality-loop`)

Одна команда в удобное время: берёт пункты `docs/quality-backlog.md`, улучшает генератор в
изолированной ветке руками headless-агента Claude Code и принимает изменение только при росте
оценки судьи на bench. В конце остаётся отчёт с роликами. Спека —
`docs/superpowers/specs/2026-10-23-night-quality-loop-design.md`.

## Запуск

Из worktree ветки задачи (не из main checkout), SSD подключён:

```sh
export MS_DATA_DIR="/Volumes/External SSD/moution-studio-materials/store"
./quality-loop --dry-run          # предпроверки и план: ничего не создаёт и не тратит
./quality-loop                    # без окна, бюджет $150
./quality-loop --hours 6 --budget-usd 120
./quality-loop --until 18:30      # ближайшие 18:30; ISO тоже поддерживается
./quality-loop --smoke --hours 2 --item Q12   # 2+2 сцены, 1 итерация
./quality-loop --resume           # последний начатый прогон; с --smoke — последний smoke
./quality-loop --resume --run 2026-10-31-1430
./quality-loop --help
```

Запускать в обычном терминале. Mac не должен засыпать, а SSD — отключаться:
`caffeinate -i ./quality-loop`.

> **Сейчас настоящий прогон не запускать.** Оркестратор исполняет код ветки агента вне
> песочницы (см. «Безопасность»); решение за человеком. До него — только `--dry-run`.

Ключ нового прогона — местные дата и время старта: `ГГГГ-ММ-ДД-ЧЧММ`, у smoke добавляется
`-smoke`. `--run` нужен прежде всего для точного `--resume`; старые ключи
`ГГГГ-ММ-ДД[-smokeN]` по-прежнему принимаются. Без `--until` и `--hours` временного окна нет:
цикл останавливают бюджет, бэклог и остальные предохранители. `--until` и `--hours` несовместимы.

## Что происходит

1. **Предпроверки** (и в `--dry-run`): `MS_DATA_DIR` с маркером хранилища; owner lock хранилища
   свободен (ADR 0007: не идёт bench, не запущен сервер); дерево без незакоммиченных правок
   отслеживаемых файлов; нет живого прогона с этим ключом и живого агента прошлого запуска; `claude` в
   PATH; `./check` зелёный; **пробный агент** (кроме `--dry-run`): `claude -p` с теми же правами,
   что у агента итерации, запускает `./check` в своей песочнице (~$0.1–0.5, несколько минут).
   Красный или `spawn EPERM` — отказ до трат на bench (см. «EPERM»). Иначе — отказ с причиной,
   ничего не меняется.
2. **Изоляция**: worktree `<main>/.claude/worktrees/night-<ключ>` (`git worktree add`), ветка
   `night/<ключ>` от текущего коммита; `make install` в нём (npm ci + браузер рендера).
3. **Базовая линия**: принятый прогон из `docs/evidence/phase-1/bench/` на этом же коммите (оба
   набора, все сцены) или прогон цикла `night-<ключ>-0-<sha>` (+`-user`).
4. **Итерация n**: верхний пункт со статусом `открыт` → ветка `night/<ключ>-<n>` от последнего
   принятого коммита → агент (`claude -p` с брифом `scripts/night-brief.md`) → разбор после
   агента → `./check` → bench explainer и user (`night-<ключ>-<n>-<sha>`, `-user`) → правило
   приёмки (`server/src/bench/night-accept.ts`).
   - **Разбор после агента:** погасить его остатки (группа процесса и процессы, запущенные им с
     рабочим каталогом в worktree цикла, — адресно, по pid); незакоммиченные правки — патчем
     `tmp/night/<ключ>/<n>/wip.patch` и копиями неотслеживаемых файлов в `<n>/wip-untracked/`
     (не stash: его стек общий для всех worktree и сессий); вернуть ветку итерации, если агент её
     сменил; сдвинуты `main`/`staging` (локально или в origin) — **остановка прогона**.
   - **Запрещённые пути:** диф `<старт>..HEAD` (`--name-only`) против `FORBIDDEN_PATHS` в
     `night.ts`: bench и судья с рубрикой и якорями, наборы, метрики, сам цикл, `check`,
     `.githooks/`, `bootstrap.sh`, `finish`, `tools/`, `Makefile`, конфиги тестов и линтера,
     `.claude/`, бэклог, `package*.json`. Пересечение → `отклонено: запрещённые пути` до `./check`,
     bench и любых commit/push оркестратора: код агента, правящий измеритель или хуки, не
     исполняется.
   - **Правило приёмки** — парный тест по сценам: средняя дельта explainer ≥ +0.1 **и** нижняя
     граница (mean − t₀.₉·SE) > 0; `--compare` «принять»; ни одна сцена explainer и user не упала
     больше чем на 1.0; user отклоняется только при уверенном падении (средняя ниже −0.2 и
     верхняя граница < 0); failed не растёт; p90 стоимости ≤ $5; медиана времени explainer
     ≤ +25 %; все сцены оценены. Пункт со строкой `приёмка: без регрессии` роста не требует.
   - **Подтверждающий прогон:** «принято» по первому прогону — ещё не итог: bench кандидата
     повторяется (`…-r2`), решение и новая базовая линия — по среднему двух прогонов (`…-avg`),
     чтобы один удачный прогон не завышал планку. Повтор не помещается в бюджет или окно:
     пограничное «принято» → сбой окружения (пункт открыт), уверенное → принято по одному
     прогону с пометкой в REPORT.
   - принято → `night/<ключ>` fast-forward на итерацию, новая базовая линия, пункт `принято`;
   - не принято → ветка итерации остаётся, пункт `не дало роста: …` вниз списка;
   - сбой изменения (таймаут агента, нет коммитов, `./check` красный, bench неполный) → пункт
     `сбой: …` вниз списка;
   - **сбой окружения** (`spawn EPERM`, хранилище, `owner_busy`, разные судьи, обрыв прогона во время
     агента, неподтверждённое пограничное «принято») → пункт **остаётся `открыт`**, в историю —
     строка `сбой инфраструктуры …`;
   - **два сбоя подряд одного рода** → остановка прогона (иначе цикл тратил бы деньги впустую).
   Пометка пункта — коммит `docs(night): …` в `night/<ключ>`; ветки пушатся в origin как копия.
5. **Остановка**: заданное окно (`--until` или `--hours`) не вмещает итерацию; бюджет
   (`--budget-usd`, по умолчанию 150) не вмещает итерацию; нет открытых пунктов;
   `--max-iterations`; выбранный
   `--item` пройден или не открыт; два сбоя подряд одного рода; сдвинуты `main`/`staging`;
   хранилище занято перед bench (сервер или чужой bench держит owner lock); SSD отключён; окно
   или бюджет кончились посреди bench — bench сам ограничен: таймаут не дальше `--until`, траты
   прогона (по файлам сцен) не больше остатка бюджета. В последних случаях итерация остаётся в
   фазе bench, `--resume` её доведёт. Прерванный агент учитывается в бюджете по его итогу, если
   он его записал, иначе по лимиту итерации.

Цикл качества не удаляет и не переписывает ветки и коммиты, не трогает `main`, `staging` и
основной worktree, не меняет настройки и права. `docs/quality-backlog.md` меняется только в
ветке прогона.

## Агент итерации

```
claude -p --output-format json --permission-mode dontAsk --permission-prompts none \
  --settings <main>/.claude/settings.json --max-budget-usd <$> --name night-<ключ>-<n> < бриф
```

Права — те же, что у сессий проекта (его `settings.json`: `dontAsk`, sandbox, allow-список,
guard); запрос разрешения в headless-прогоне некому подтвердить, поэтому он отклоняется и
попадает в отчёт
(«блоки прав»). Лимиты на итерацию: время (`--agent-min`, 120; режется окном), деньги
(`--agent-usd`, 30; режется остатком бюджета). Агент не запускает bench и платные прогоны.

## Где что лежит

- `tmp/night/<ключ>/state.json` — состояние (для `--resume`), `REPORT.md` — отчёт прогона
  (пересобирается после каждого шага), `<n>/brief.md`, `<n>/agent.json|err`, `<n>/check.log`,
  `<n>/wip.patch`, `<n>/wip-untracked/`, `<n>-bench-*.log`, `<n>-r2-bench-*.log`, `prepare.log`,
  `preflight-check.log`, `probe/` (пробный агент).
- `<worktree цикла>/tmp/bench/night-<ключ>-<n>-*` — прогоны bench итераций (`-r2` — подтверждающий,
  `-avg` — среднее двух).
- `<main>/tmp/motion-studio-examples/night-<ключ>-<n>/` — ролики принятых итераций с README.

## После прогона

Прочитать `tmp/night/<ключ>/REPORT.md` (время в нём — местное), посмотреть ролики,
`git log night/<ключ>`. Влить в ветку задачи после ревью: `git merge --ff-only night/<ключ>`. Не
принятые ветки `night/<ключ>-<n>` — для разбора; вернуть пункт в очередь — статус `открыт` в
`docs/quality-backlog.md`.

**«Принято» — не доказательство роста.** Разброс судьи и генерации ~0.5–1.0 на сцену; парный
тест и подтверждающий прогон снижают долю ложных решений, но не убирают её. Смотреть ролики.

Остатки агента: `git apply --index tmp/night/<ключ>/<n>/wip.patch` в ветке итерации (+ файлы из
`<n>/wip-untracked/`). Smoke до 2026-10-23 клали остатки в stash — смотреть
`git stash show -p <sha>`, **не** `pop`.

## Уборка

Цикл ничего не удаляет. Убирает человек, когда прогон разобран:
- worktree цикла (`<main>/.claude/worktrees/night-<ключ>`, в каждом `node_modules` и браузер
  рендера, ~1–2 ГБ): `git worktree remove .claude/worktrees/night-<ключ>` из основного checkout;
- ветки: локальные `git branch -D night/<ключ> night/<ключ>-<n> …`, в origin
  `git push origin --delete night/<ключ> …`;
- журналы `tmp/night/<ключ>/` в worktree запуска и прогоны `tmp/bench/night-<ключ>-*` внутри
  worktree цикла (уходят вместе с ним); ролики `tmp/motion-studio-examples/night-<ключ>-*` — по
  желанию.

## Безопасность (решение человека)

- Агент работает в песочнице (`claude -p` с `settings.json` проекта и guard). А **оркестратор**
  запущен из обычного терминала и исполняет код ветки агента без песочницы: `./check` (тесты и
  линтеры ветки), bench (генератор, рендер, судья; сеть без allowlist) и `make install` при
  `--resume`. Запрещённые пути закрывают подмену хуков, `check`, зависимостей и измерителя, но
  не тест с побочным эффектом в обычном коде. Пока человек не решил, как это закрыть (отдельная
  песочница для `./check` и bench или согласие на риск), настоящий прогон не запускать.
- Хуки git в worktree цикла — из рабочего дерева текущей ветки (`core.hooksPath=.githooks`).
  Оркестратор коммитит и пушит только из ветки прогона, куда правки `.githooks/` попасть не могут:
  итерация с ними отклоняется (запрещённые пути). Путь к хукам цикл не переопределяет.

## EPERM

Пробный агент или REPORT пишут `spawn EPERM` — песочница агента не даёт `./check` запускать
дочерние процессы (тесты с `ps`, owner lock, генерация). Тогда агент не сможет коммитить
(pre-commit): прогон не начинается (пробный агент) или останавливается после двух таких сбоев, не
трогая статусы пунктов. В smoke 2026-10-23 так было при запуске прогона из сессии Claude Code
(вложенная песочница); из обычного терминала не проверено. Если EPERM и из терминала — нужно
решение человека о правах песочницы (`.claude/settings.json`: `sandbox`, `excludedCommands`).
Цикл качества права не меняет.

## Тестовый двойник агента

`MS_NIGHT_CLAUDE_BIN=<скрипт>` подменяет `claude` — только для проверки механики (smoke).
Двойник исполняется и в предпроверке (`--version`) в worktree запуска, поэтому должен отвечать на
`--version` и отказываться работать вне `worktrees/night-*`. Пробный агент с двойником
бессмыслен — `--skip-probe`. Для настоящего прогона переменная не задаётся.
