# Motion Studio — отдельное Node/TS-приложение в my-remotion

**Контекст.** ТЗ (`AI_Motion_Studio_TZ.md` v1.2) требует React/TS-интерфейс,
Remotion-композиции, Knowledge Base из my-remotion, durable jobs с восстановлением
после рестарта и иммутабельные версии; при этом просит переиспользовать существующий
backend и UI, если это оправдано (§3.4, §12), и не менять ai-platform без согласования
(§16.3). Backend ai-platform — Python stdlib, UI — ванильный JS без сборки, очередь —
один поток, после рестарта задачи остаются `interrupted`. ASR и генерация изображений
ai-platform доступны как независимые сервисы (§2.1). Устаревший `aiplatform/motion/`
исключён из источников решений по указанию человека (2026-10-20) и на это решение
не влияет.

**Решение.** Строим `app/motion-studio/` в my-remotion. ai-platform используем как
поставщика ASR через CLI-воркер и, опционально, изображений через HTTP. Движок сцен
(`contracts/` + `render/`) не зависит от HTTP и БД — ради тестируемости и
воспроизводимого рендера по сохранённым файлам (ТЗ §6.3).

**Последствия.** Один тулчейн с Remotion и KB; ai-platform не меняется. Транскрипт,
rough cut и таймлайн (Phase 2–5) проектируются по ТЗ с нуля. Интеграция с ai-platform
ограничена ASR и изображениями; её контракт фиксируется коммитом ai-platform.
