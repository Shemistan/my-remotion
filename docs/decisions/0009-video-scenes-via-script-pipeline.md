# Видеосцены через сценарный конвейер

**Контекст.** План Phase 4–6 (редакция 2026-10-21) строил отдельный производственный конвейер
сцен видеопроекта: задачи `production.generate/edit/batch`, `scene.import`, общий
`runScenePipeline`, выделенный из `playgroundGenerate`, свои таблицы `production_scenes`,
`batches`, `prod_timelines`, бюджетный гейт пакета, холсты размером зоны для pip и split_screen,
изменение длительности сцены с таймлайна (`set_duration`/`retime`). Пока он ждал, сценарный трек
(S1–S18, спека `2026-10-24-script-to-motion-design.md`) сделал почти то же для текста: вход
`script` у `playground.generate`, пакет как набор обычных задач с ключами (`server/src/script/batch.ts`),
отпечаток сцены плана, прозрачный экспорт через `props.style.transparent` (S6), фиксированную
длительность сцены в правке (S16a), папку клипов с шпаргалкой (`script.package`, `exportOne`).
Сверка плана с кодом 2026-10-25 показала, что редакция 2026-10-21 дублирует этот конвейер и
противоречит ему (миграции 003/004 уже заняты, `ScriptSceneContextSchema` — готовый образец,
блокировка длительности S16a). Анализ Phase 3 (`docs/evidence/phase-3/REPORT.md`, F6): автор в
центре кадра, половина экрана под split_screen закрывает 46 % лица.

**Решение** (человек, 2026-10-25: «Согласен с твоими рекомендациями»).

1. **Р-V1.** Сцены видеопроекта генерируются тем же `playground.generate`/`playground.edit` с новым
   входом `video` рядом со `script`; `production.*` и `runScenePipeline` не делаются.
2. **Р-V2.** Пакет сцен — набор обычных задач, как `script/batch.ts` (`stageBatch`, ключи,
   `job_events`, `batchStatus`, `cancelBatch`); ключ задачи
   `video:<plan>@r<rev>:<item>:s<style>[:try-n][:regen-k]`; нужно валидное Approval B.
3. **Р-V3.** Хранение — новые таблицы `video_scenes`/`video_batches` по образцу `script_*`;
   `script_*` не обобщаются. Все новые типы задач и таблицы Phase 4–6 — одной миграцией `006`.
4. **Р-V4.** Approval C — на версию сцены; субъект `scene:<id>@r<номер версии>` + хеш манифеста
   версии; финал — `timeline:<id>@r<N>` + хеш настроек экспорта. Отзыв и поиск — по субъекту, не
   по всем решениям вида в проекте; таблица `approvals` пересобирается миграцией (`subject_key`).
5. **Р-V5.** Все размещения рендерятся на весь кадр: `fullscreen` — непрозрачно, остальные —
   прозрачно, графика только в `layout.rect` (необязательное поле `ScenePropsBase`). При лице в
   центре кадра split_screen не предлагается (автор не перекадрируется).
6. **Р-V6.** Длительность видеосцены меняется только через план: границы по словам → новая
   ревизия → пересборка сцены с новой плановой длиной. Retime с таймлайна в обход блокировки S16a
   не делается.
7. **Р-V7.** Бюджетного гейта пакета нет: стоимость справочная (как Р10 сценарного трека).
8. **Р-V8.** Task 50 (motion-kit 0.3, рубрика) заменяется треком качества (S16b + ночные прогоны),
   последним; версии kit — от 0.5.8 (следующая 0.5.9).
9. **Р-V9.** Сначала Phase 5-lite: папка клипов видеопроекта (MP4 + ProRes 4444 с альфой +
   шпаргалка с таймкодами исходника и смонтированного ролика) через механизм
   `script.package`/`exportOne`; затем полная Phase 5.

**Альтернативы.**

- *Отдельный производственный конвейер (редакция 2026-10-21).* Отвергнута: второй путь генерации
  и правок той же сцены, двойные тесты и расхождение качества с Playground; S1–S18 уже дают пакет,
  отпечатки, альфу и папку.
- *Обобщить `script_*` в общие таблицы «сцен плана».* Отвергнута: миграция живых данных
  сценария и риск сломать готовый трек ради экономии двух таблиц.
- *Холст размером зоны для pip и split_screen с масштабированием.* Отвергнута: новый класс
  холста, проверка `<Sequence width height>` на 4.0.537, смена зоны — только перегенерацией;
  прозрачный рендер на весь кадр уже проверен альфа-экспортом S6.
- *Перекадрировать автора под split_screen.* Отвергнута: нет поля и проверки в плане, нужен
  второй трек видео; проще не предлагать split_screen при лице в центре.
- *Изменение длительности с таймлайна масштабированием темпа.* Отвергнута: обходит блокировку
  длительности S16a и ломает синхронизацию с речью; граница сцены — слово плана.
- *Бюджетный гейт пакета.* Отвергнут: подписка, стоимость справочная; лимиты вызова агента
  (`agents.<role>.maxBudgetUsd`) и задачи (`scene.maxCostUsd`) остаются.

**Последствия.**

- План Phase 4–6 переписан (редакция 2026-10-25): задачи 35′, 36, 37′, 38-39, 40, 5L, 41–48,
  49a, 49b, 51, 52; Task 50 заменена; волны В1–В8. Брифы — `v2-task-<id>-brief.md`.
- Общий код сценария (`playground-generate.ts`, `playground-edit.ts`, `script/batch.ts`,
  `export-version.ts`) меняется задачами видео; сценарные тесты и e2e с реальным `claude` —
  обязательная защита этих задач.
- Отпечаток видеосцены не включает абсолютную позицию в ролике: правка EDL до сцены сдвигает её,
  не делая устаревшей; смена слов, режима, зоны, длительности — делает.
- Перемещение сцены на таймлайне остаётся (в пределах якорей), смена длительности, режима и зоны —
  только через план.
- ADR 0008 (один Remotion-движок для финала) остаётся за Task 36.
