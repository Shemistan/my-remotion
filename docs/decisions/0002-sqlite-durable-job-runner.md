# SQLite и собственная durable-очередь задач

**Контекст.** Нужны переживающие рестарт задачи, идемпотентность, cancel/retry,
связи project → scene → version → agent run → render job. Пользователь один,
задач — единицы. ТЗ запрещает Redis и микросервисы без необходимости. ai-platform
хранит состояние в JSON-файлах и после рестарта ставит `interrupted` без автоповтора.

**Решение.** SQLite в режиме WAL (`better-sqlite3`) для метаданных и очереди
(таблица `jobs` с lease/heartbeat), файловая система для медиа и иммутабельных
версий с `manifest.json`. Миграции — SQL-файлы с `PRAGMA user_version`.

**Последствия.** Атомарные переходы статусов, простые запросы для UI и журнала.
Нативный модуль `better-sqlite3` требует сборки или prebuilt-бинарника для arm64.
Масштабирование на нескольких пользователей потребует другой БД — вне MVP.
