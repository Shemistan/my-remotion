# Visual Knowledge Base для Remotion

## Задача

Превратить клонированные репозитории в `templates/` (инфографика, React-
анимации, Remotion-компоненты) и `official_skills/` в структурированную базу
визуальных возможностей для агентов AI-монтажа: агент-режиссёр подбирает
решение по смыслу озвучки, агент-разработчик читает исходники только
выбранного решения.

## Решение

- `knowledge/` в корне проекта: `README.md`, `taxonomy.md`,
  `repositories.json`, `capabilities.jsonl`, `components/<repo>/*.md`,
  `patterns/*.md`, `compatibility/`.
- Единица каталога — **возможность** (component / example / template /
  chart-type / diagram-type / hook / util / doc) с фиксированным набором
  полей (см. `knowledge/README.md`). Фразы озвучки — по-русски.
- `capabilities.jsonl` собирается из per-repo файлов
  `components/<repo>/capabilities.jsonl` (`tools/kb.py build`), чтобы
  репозитории обрабатывались и фиксировались независимо.
- Совместимость с Remotion — пять классов (`native / adaptable / complex /
  unsuitable / unknown`) плюс флаги зависимостей (CSS-анимации, rAF, DOM,
  события, движки, Canvas/WebGL, async). Статус `rendered-*` допустим только
  при записи в `compatibility/results.jsonl`.
- Контроль качества — `tools/kb.py check`, подключён в `./check`: пути к
  исходникам существуют, id уникальны, перечисления валидны, у каждой записи
  сценарии и ≥2 фразы озвучки, лицензии репозиториев заполнены, паттерны
  ссылаются на существующие id.
- Исходные репозитории не изменяются и не коммитятся (вложенные git-клоны,
  ~5 ГБ); фиксируется их URL и commit в `repositories.json`.

## Ограничения

- Без установки зависимостей и рендеринга: статус проверки — не выше
  `static-review`.
- Карточки короткие; гигантские библиотеки (echarts, recharts, nivo)
  описываются по типам графиков, а не по всем внутренним модулям.
- Пилот — `remotion-bits`; формат фиксируется на нём, потом тиражируется
  субагентами с единым протоколом.
