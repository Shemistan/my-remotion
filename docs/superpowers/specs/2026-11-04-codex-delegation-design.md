# Делегирование работы агентов в Codex

## Задача

Пользователь хочет, чтобы часть вызовов агентов шла не в Claude Code, а в Codex CLI
(вторая подписка), чтобы:

- включать и выключать это в настройках;
- регулировать долю: от минимально возможной до максимума, при котором качество не падает.

## Факты (база студии на 2026-11-04)

Доля стоимости вызовов Claude по ролям (`agent_runs`, все прогоны):

| Роль | Доля |
|---|---|
| engineer | 61,9 % |
| motion_director | 27,4 % |
| visual_qa | 9,7 % |
| concept | 1,0 % |
| прочие | ≈0,1 % |

Вывод: передача целых «лёгких» ролей почти ничего не экономит. Регулятор должен
делить вызовы внутри тяжёлых ролей.

## Решение

### 1. Рантайм `CodexRuntime`

Второй адаптер `AgentRuntimeAdapter` (интерфейс уже заложен ADR 0003):
`codex exec --json --ephemeral --skip-git-repo-check -C <workdir> -s <sandbox>
--output-schema <schema> -o <last.json> [-m <model>] [-c model_reasoning_effort=…]`,
промпт (системный промпт роли + задача) — через stdin.

- Песочница: `read-only` для ролей без Write/Edit, `workspace-write` для engineer
  (писать можно только в draft-каталог). Сеть в песочнице Codex выключена.
- Схема ответа: JSON Schema из Zod приводится к строгому виду (все поля
  `required`, необязательные — `anyOf [..., null]`); ответ: `null` у необязательных
  полей удаляется, затем проверка той же Zod-схемой.
- Usage: токены из события `turn.completed`; `costUsd = 0` (подписка), модель в
  журнале — `codex:<model>`: так прогоны Codex отличимы в `agent_runs`.
- Журналы, TMPDIR, реестр процессов, таймаут и отмена — как у `ClaudeCodeRuntime`.

Отступление от ADR 0003: у Codex есть shell (в его песочнице, без сети, запись
только в cwd). Фиксируется ADR 0011.

### 2. Маршрутизатор `RoutingRuntime`

Обёртка над обоими рантаймами; решает для каждого вызова, кто его выполняет.

**Предохранители качества (не настраиваются из UI):**

1. `visual_qa` всегда Claude: судья не должен совпадать с исполнителем.
2. Исправления (engineer `seq ≥ 100`) и повторные попытки задачи
   (`attempt > 1`) — Claude: если первый дубль Codex не прошёл, чинит сильная модель.
3. Сбой Codex (schema, cli, timeout) — тот же вызов сразу перезапускается в Claude.
   У engineer перед вызовом Codex снимается копия draft-каталога; при сбое черновик
   восстанавливается из неё, и Claude начинает с того же состояния. Не удалось снять
   или восстановить копию — сбой уходит в штатный цикл исправлений (п. 2).
4. Авто-пауза роли: по последним 20 задачам с первым дублем Codex сравнивается
   «чистота» с Claude: engineer — доля задач без исправлений, прочие роли —
   доля успешных вызовов. Если при n ≥ 8 Codex хуже Claude больше чем на
   15 п. п., роль ставится на паузу и до сброса в UI идёт в Claude.

**Регулятор `delegation.level` (0–100 %)** — целевая доля работы (по стоимости
Claude) для Codex. Роли заполняются в порядке риска для качества:

1. Структурные роли: fragment_fit, footage_analyst, rough_cut_editor,
   edit_planner, concept, semantic_director, script_director, visual_planner.
2. engineer — код по готовой спеке; ловят tsc, рендер и QA.
3. motion_director — творческое ядро сцены, идёт последним.

Каждая роль получает долю вызовов `f ∈ [0, 1]`: роли берутся по порядку, пока
сумма их весов не достигнет `level`; последняя берётся частично. Вызов идёт в
Codex, если `hash(runId, role, seq) / 2³² < f`: так решение детерминированно и
повторяемо.

Веса ролей — доли стоимости из `agent_runs` за последние 30 дней (только вызовы
Claude). Если истории нет — встроенные веса из таблицы выше.

- **Минимум** — первая ступень больше нуля: только структурные роли (≈1–2 %).
- **Безопасный максимум** — сумма весов ролей, у которых
  нет авто-паузы. По умолчанию
  motion_director помечен `unverified`: в безопасный максимум он не входит, пока
  пользователь явно его не включит. Без него максимум ≈ 63 %; со всеми ролями,
  кроме visual_qa, — ≈ 90 %.

### 3. Настройки и UI

`config.json`:

```json
"codex": { "bin": "codex", "model": "<необязательно>", "reasoningEffort": "high" },
"delegation": { "enabled": false, "level": 0, "allowUnverified": false }
```

- `codex.bin` — только правкой файла: как `claudeBin` (F2).
- `delegation.*` меняется из UI (`PUT /api/settings`) и применяется сразу, без
  перезапуска: маршрутизатор получает новую политику из обработчика PUT.
- Страница «Настройки», блок «Делегирование в Codex»: переключатель «Вкл», ползунок
  с отметками «минимум» и «безопасный максимум», флажок «разрешить роли без
  проверки качества (motion_director)», таблица ролей: вес, доля вызовов в
  Codex, статистика чистоты Codex/Claude, статус (активна / пауза / всегда
  Claude) и кнопка «Снять паузу». Оценка: «≈ X % работы уходит в Codex».
- `GET /api/delegation` — текущая политика, план долей, статистика; `POST
  /api/delegation/resume/:role` — снять паузу.
- `doctor` и `/health` показывают доступность `codex` (`codex --version`).

## Вне объёма

- Codex для visual_qa и для бенч-судьи.
- Учёт лимитов подписки Codex: при ошибке квоты срабатывает фолбэк в Claude
  (п. 3) или цикл исправлений.
- Калибровка «безопасного максимума» бенчмарком: авто-пауза меряет качество на
  реальной работе. Бенч-сравнение — следующий шаг после живых прогонов.
