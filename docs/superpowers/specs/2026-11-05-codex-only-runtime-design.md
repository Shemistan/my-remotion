# Codex-only: полный runtime и контур качества

## Задача

Claude Code остаётся основным инструментом, но после исчерпания его лимита
пользователь должен переключить студию на Codex целиком. В этом режиме нельзя
скрыто расходовать лимит Claude: если Codex не ответил, задача должна явно
завершиться ошибкой, а не повторить вызов в Claude.

## Решение

### 1. Три явных режима

`agentRuntime` имеет три значения:

- `claude-code` — все роли, QA, исправления и повторы идут в Claude;
- `hybrid` — действует существующая политика делегирования с защитными
  фолбэками в Claude;
- `codex-only` — все вызовы без исключений идут в Codex; фолбэка в Claude нет.

Переключение из UI записывается в `config.json` и действует со следующего вызова
агента, без перезапуска. Уже идущий вызов не переносится между runtime.

Для совместимости старый `config.json` без `agentRuntime`, но с
`delegation.enabled: true`, загружается как `hybrid`; без включённой делегации —
как `claude-code`.

### 2. Маршрутизация и ошибки

`RoutingRuntime` хранит текущий режим и меняет его атомарно для следующего
вызова. В `codex-only`:

- `visual_qa`, `motion_director`, engineer-fix (`seq >= 100`) и `attempt > 1` не считаются
  исключениями;
- автопауза гибридной делегации не влияет на маршрут;
- `failed`, `timeout`, schema/CLI/quota ошибка Codex возвращается пайплайну
  без вызова Claude.

В `hybrid` сохраняются все прежние предохранители. Это не меняет поведение
пользователей гибридного режима.

### 3. Настройка качества Codex по ролям

Глобальные `codex.model` и `codex.reasoningEffort` остаются базой. В `config.json`
добавляются необязательные профили:

```json
{
  "codex": {
    "model": "gpt-5.1-codex-max",
    "reasoningEffort": "high",
    "agents": {
      "motion_director": { "reasoningEffort": "xhigh" },
      "visual_qa": { "reasoningEffort": "xhigh" }
    }
  }
}
```

Профиль роли перекрывает только заданные поля. `bin` и профили Codex из
браузера не меняются: как и `claudeBin`, это ручной административный конфиг.

### 4. UI и наблюдаемость

В блоке Codex на странице настроек появляется выбор режима. Для `hybrid`
видны ползунок и предохранители. Для `codex-only` UI явно пишет, что фолбэка
в Claude нет. Недоступный Codex CLI нельзя выбрать как `codex-only`.

`GET /api/delegation` отдаёт текущий режим и фактические доли ролей: 0 % в
`claude-code`, план в `hybrid`, 100 % в `codex-only`.

### 5. Воспроизводимый bench

`bench-set.mts --runtime claude|hybrid|codex` перекрывает runtime только для данного
прогона. В `run.json` и `gen.json` записываются режим, модель, reasoning effort и
поролевые профили Codex. Продолжить генерацию того же run id с другим runtime
нельзя. Судья пока остаётся Claude и явно помечается отдельно: одинаковый
внешний судья нужен для честного A/B генераторов.

## Критерии приёмки

- Тест маршрутизатора доказывает, что в `codex-only` все роли, фиксы и повторы
  попадают в Codex.
- Тест сбоя доказывает, что в `codex-only` Claude не вызван.
- Смена режима через `PUT /api/settings` видна следующему решению маршрутизатора
  без перезапуска.
- Старые config и гибридный режим сохраняют прежнее поведение.
- Unit/UI-тесты и `./check` проходят; реальный дорогой A/B запускается отдельно
  после мержа и фиксации базовой линии.

## Вне объёма

- Автоматическое переключение по ответу API об лимите Claude.
- Замена Claude-судьи bench на Codex.
- Обещание паритета качества без полных прогонов bench: эта итерация создаёт
  управляемый и измеряемый контур для доводки.
