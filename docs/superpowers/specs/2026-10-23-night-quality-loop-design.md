# Ночной цикл качества видео

Решение пользователя 2026-10-22: доводка качества генерации до ≥ 7.5 (судья) идёт не в дневном
потоке, а ночным циклом, который запускается одной командой и к утру даёт отчёт с роликами.

## Что делает

Команда `./night` в корне репозитория (обёртка над `app/motion-studio/scripts/night.mts`).

1. **Предпроверка.** SSD подключён (`MS_DATA_DIR`), `./check` зелёный, рабочее дерево чистое,
   нет другого запущенного bench (owner-lock ADR 0007). Иначе — отказ с понятным сообщением,
   ничего не меняется.
2. **Изоляция.** Отдельный git worktree `.claude/worktrees/night-<YYYY-MM-DD>` и ветка
   `night/<YYYY-MM-DD>` от текущей ветки задачи. В основной worktree, `main` и `staging` ночь
   ничего не пишет и не пушит.
3. **Базовая линия.** Последний принятый прогон bench на обоих наборах (`explainer` 12 сцен,
   `user` 6 сцен) из `docs/evidence/phase-1/bench/`; если для текущего коммита его нет — ночь
   сначала делает его сама (одна итерация уходит на это).
4. **Итерации** до исчерпания окна (по умолчанию до 07:00 местного времени, флаг `--until`)
   или бюджета (`--budget-usd`, по умолчанию 150):
   - берёт верхний открытый пункт из `docs/quality-backlog.md`;
   - запускает headless-агента Claude Code (`claude -p`, те же `.claude/settings.json` и guard,
     без расширения прав) с брифом: пункт бэклога, правила `CLAUDE.md`, TDD, `./check` зелёный,
     коммиты в ветке итерации; лимит итерации по времени и деньгам;
   - прогоняет bench на обоих наборах с судьёй (`--run night-<дата>-<n>-<sha>`);
   - **правило приёмки:** среднее explainer выросло ≥ +0.1 и `--compare` = «принять»;
     среднее user не упало больше чем на 0.2; число failed не выросло; p90 стоимости сцены
     ≤ $5; медиана времени генерации explainer не выросла больше чем на 25 %;
   - каждая итерация работает в своей ветке `night/<дата>-<n>` (не `night/<дата>/<n>`: git не держит ветку и каталог веток с одним именем) от последнего принятого коммита;
     принято → `night/<дата>` двигается на неё fast-forward, новая базовая линия = этот прогон,
     пункт помечается `принято (ночь <дата>)`; не принято → ветка итерации остаётся для разбора
     (ничего не откатывается и не удаляется), следующая итерация стартует от последнего
     принятого, пункт помечается `не дало роста (ночь <дата>): <цифры>` и уходит вниз списка.
5. **Утренний отчёт** `tmp/night/<дата>/REPORT.md` (по-русски): что пробовали, цифры до/после по
   обоим наборам и по осям рубрики, что принято, стоимость и время, ссылки на ролики. Ролики
   принятых итераций копируются в `tmp/motion-studio-examples/night-<дата>-*` с README.
   Утром контроллер (дневная сессия) вливает ветку `night/<дата>` в ветку задачи после ревью.

## Безопасность

- Никаких новых прав: агент ночи живёт под теми же guard и sandbox; заблокированная операция —
  запись в отчёт, не обход.
- Данные только в `MS_DATA_DIR`; при отключении SSD — остановка, не системный диск.
- Сбой итерации (таймаут агента, падение bench) не останавливает ночь: откат и следующий пункт.
- Повторный запуск в ту же ночь продолжает (`--resume`), а не начинает заново.

## Бэклог (начальное содержание `docs/quality-backlog.md`)

S4 библиотека сценографий; порог и режим второго дубля (A/B revise/fresh, порог 7.0–7.5);
пустой кадр после ухода cold-open-крючка; живые финалы abtest/funnel; ошибка схемы Director
(oauth); `missing_element` в gen-cache; text_overlap choreo-gallery; m1 «мир» по ширине;
калибровка Visual QA против судьи (+1.1); ревью дизайнера 3; трек иллюстративной анимации для
набора user (камера с отъездом scale < 1, персонажи/морфинг, рендер длинных сцен).

## Вне рамок

Изменение рубрики судьи и набора сцен (сломает сравнимость) — только днём, решением человека.
