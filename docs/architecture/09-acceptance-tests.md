# 09. Приёмочные тесты

Общие правила (ТЗ §14): реальные модели и реальный рендер; mock/stub не засчитываются;
evidence сохраняется в `docs/evidence/phase-N/<test>/` (превью ≤ 10 МБ, кадры PNG,
QA-отчёт, manifest, журнал задач, стоимость); в отчёте для каждого пункта указано
**[A]** — проверено автоматически или **[H]** — требует просмотра человеком.

## 1. Критерии готовности Motion Playground (Phase 1)

Пользователь в UI может **создать, посмотреть, исправить, восстановить и
экспортировать** реальную Remotion-сцену, собранную с опорой на индексированную KB:

1. Версия содержит `knowledge-refs.json` хотя бы с одной записью KB с `repo`,
   `commit`, `license`, `strategy`. [A]
2. `preview.mp4` получен реальным `renderMedia`, ffprobe: длительность ± 1 кадр,
   размеры и fps совпадают с настройками. [A]
3. Код версии прошёл typecheck и статическую проверку. [A]
4. Ошибка рендера показывается как ошибка с логами, а не как preview. [A: тест с
   заведомо сломанной сценой]
5. После перезапуска сервера сцена открывается, все версии на месте, экспорт
   повторяется и даёт файл с той же длительностью и размерами. [A]
6. Исходники KB и оригиналы не изменены (sha256 до/после по выборке файлов). [A]

## 2. Test 1 — Data Storytelling

Промпт: «Создай премиальную анимацию роста пользователей с 10 000 до 1 000 000 за
три года. Тёмный фон, крупная типографика, плавное движение графика, акцент на
конечном значении».

| Проверка | Как | Тип |
|---|---|---|
| Сцена содержит график с ≥ 3 точками/периодами и подписью лет | spec содержит chart-бит; на кадре середины графика видна линия, проверка QA | A + H |
| Числа анимируются от 10 000 до 1 000 000 | кадры начала и конца числового бита: OCR-проверка QA-агентом значений «10 000» и «1 000 000» (формат RU) | A |
| Тёмный фон | средняя яркость кадров < 25 % | A |
| Акцент на финальном значении | spec: отдельный бит emphasis в конце; на последних кадрах финальное число — самый крупный текст | A + H |
| Читаемость | размер основного текста ≥ 4 % высоты кадра; контраст ≥ 4,5:1 по палитре | A |
| Нет обрезки | QA: элементы в safe area | A + H |
| Стабильный рендер | повторный рендер той же версии: sha256 3 ключевых PNG совпадают | A |
| Экспорт | MP4 H.264/AAC, 1920×1080, 30 fps | A |

## 3. Test 2 — Technical Explainer

Промпт: «Покажи архитектуру AI-агента: пользователь отправляет запрос, оркестратор
вызывает три инструмента, данные возвращаются обратно. Световые импульсы движутся
по связям».

| Проверка | Как | Тип |
|---|---|---|
| Узлы: Пользователь, Оркестратор, 3 инструмента | spec содержит ≥ 5 узлов с этими ролями; подписи видны на кадре hold | A + H |
| Направление: запрос → оркестратор → инструменты → обратно | биты spec упорядочены; импульсы на кадрах битов идут в нужную сторону (QA по паре соседних кадров) | A + H |
| Импульсы по связям | `PulseAlongPath` (или адаптация `magicui/animated-beam`) в knowledge-refs; на соседних кадрах позиция импульса меняется | A |
| Выбор из KB с источниками | knowledge-refs содержит ≥ 1 запись из паттерна `system-structure` с commit и лицензией | A |
| Нет перекрытий | QA: bounding boxes узлов не пересекаются (из spec-раскладки) + проверка по кадру | A + H |

## 4. Test 3 — Iterative Editing (после Test 2)

Промпт: «Уменьши скорость анимации на 25 %, сделай карточки более объёмными,
сохрани композицию и верни цветовую палитру из первой версии».

Перед тестом: у сцены ≥ 2 версий, во второй палитра изменена отдельной правкой
(например «сделай всё в фиолетовых тонах»).

| Проверка | Как | Тип |
|---|---|---|
| Новая версия от текущей, история цела | `parent_version_id` = текущая; все предыдущие версии открываются и проигрываются | A |
| Скорость −25 % | `duration_frames` и границы битов × 1/0,75 (± 1 кадр) | A |
| Карточки объёмнее | `elevation` карточек или параметры теней выросли; визуально заметно | A + H |
| Композиция сохранена | позиции узлов в spec совпадают с базой (± 2 % кадра); QA сравнивает кадры hold | A + H |
| Палитра из v1 | токены палитры = токены v1 | A |
| Нет регрессии рендера | технический gate pass, длительность/размеры корректны | A |

## 5. Тест устойчивости (Phase 1)

1. Запустить генерацию, убить процесс сервера во время рендера.
2. Запустить сервер: задача продолжена с последнего завершённого шага или помечена
   `failed(interrupted)` с возможностью retry; другие сцены не затронуты. [A]
3. Повторный POST с тем же `Idempotency-Key` не создаёт дубль. [A]
4. Сцена со сломанным кодом не блокирует очередь; ошибка видна в UI с логами. [A]
5. Хранилище недоступно (`MS_DATA_DIR` переименован или указывает на каталог системного
   тома с чужим маркером): задачи не стартуют, сервер в режиме `storage_offline`, на
   системный диск ничего не записано; после возврата каталога работа продолжается. [A]
6. Реальное отключение внешнего SSD во время рендера: то же поведение, опубликованные
   версии целы. [H — ручной тест с физическим отключением]

## 6. Автотесты уровня кода (входят в `make check`)

- `contracts`: валидные/невалидные фикстуры для каждой схемы; `time.ts` (29,97 fps, округления).
- `jobs`: переходы статусов, lease, рестарт, cancel, retry, идемпотентность.
- `knowledge`: golden-запросы, `license_class`, `exists:false`.
- `scenes`: иммутабельность (запись в опубликованную версию → ошибка), восстановление, diff.
- `static-check`: фикстуры с `fetch`, `Math.random`, `setTimeout`, неразрешённым импортом.
- `agents`: парсинг ответов CLI (успех, `is_error`, нарушение схемы, таймаут) на
  записанных реальных ответах.
- Интеграционные (отдельная цель `make e2e`, не в pre-commit — требуют сеть и
  стоимость): реальный `claude` на дешёвой модели, реальный рендер тестовой сцены.

## 7. Test 4 — Talking Head (после Phase 5)

Как в ТЗ §14: реальный ролик 60–120 с, предоставленный пользователем. Проверки:
ASR со временем слов, rough cut обратим, маппинг source↔edited (выборочно 10 слов
± 1 кадр), предложения графики не закрывают лицо, approvals A/B/C, сцены overlay и
fullscreen, синхронизация (смещение речи ≤ 1 кадр по 5 контрольным словам),
финальный MP4 воспроизводится из сохранённого проекта.
